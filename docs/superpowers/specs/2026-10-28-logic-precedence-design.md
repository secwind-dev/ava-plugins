# Design: ลำดับความสำคัญเมื่อ logic ขัดกับ Ava

- วันที่: 2026-10-28
- สถานะ: รอ owner review
- เวอร์ชันเป้าหมาย: v2.2.0

## ปัญหา

section `## 🧩 Active Logics` ใน `AVA.md` เขียนลำดับไว้แค่ "`RULE.md` ชนะเสมอ → บรรทัดบนชนะบรรทัดล่าง" แต่ไม่ได้บอกว่า logic ที่เปิดใช้มีผลเหนือกฎใน `AVA.md` / `SOUL.md` หรือไม่ เมื่อเปิด logic อย่าง superpowers ข้อความใน AVA.md จึงยังขัดกับ logic อยู่ (เช่น "ไม่แน่ใจให้ถามก่อน" กับ "ตัดสินเองตอน execute") และ model ต้องเดาเองว่าจะเชื่ออันไหน

นอกจากนี้ `ava-use-logic` ขั้น A4 ยังบังคับให้ถาม owner ทีละข้อทุกจุดที่ชนกับ Ava (superpowers มี 8 ข้อ) ทั้งที่การสั่งเปิด logic ก็คือการอนุญาตอยู่แล้ว

## เป้าหมาย

1. ไม่มี logic เปิดใช้ → Ava ทำงานแบบเดิมทุกอย่าง
2. logic ที่เปิดใช้ขัดกับกฎของ Ava → ทำตาม logic เพราะ owner อนุญาตแล้วตอนเปิดใช้
3. logic ขัดกันเองตั้งแต่ 2 ตัวขึ้นไป → owner ตัดสิน แล้วบันทึกไว้ ไม่ต้องถามซ้ำ
4. ใช้ได้กับทุก logic ไม่ผูกกับ superpowers
5. ผู้ใช้เดิมอัปเดตได้ผ่าน `/ava-check`

## ไม่อยู่ในขอบเขต

- การติดป้ายกฎใน AVA.md ว่าข้อไหน "ปรับได้" / "ล็อก" — ตอนนี้ตัวที่ล็อกจริงมีแค่ `RULE.md` ซึ่งชนะอยู่แล้ว (YAGNI)
- การคัดลอกการตัดสินใจของ owner ไปเขียนซ้ำใน AVA.md — ข้อมูลจะอยู่ 2 ที่แล้วไม่ตรงกัน

## ลำดับความสำคัญใหม่

```
RULE.md
  → การตัดสินใจที่ owner บันทึกในคอลัมน์ "owner ตัดสิน" ของ LOGIC.md
  → logic ที่เปิดใช้ (ชนกันเอง = ถาม owner)
  → กฎปกติของ Ava ใน AVA.md / SOUL.md
```

- `RULE.md` ชนะทุก logic — เป็นกฎความปลอดภัย และเป็นตัวบังคับ Startup Sequence
- คอลัมน์ "owner ตัดสิน" **ว่าง = ใช้แบบ logic** · มีค่า = ใช้ตามที่เขียน (owner ปรับเป็นทางกลางได้)
- กฎ "บรรทัดบนชนะบรรทัดล่าง" เลิกใช้ — ลำดับบรรทัด import ไม่มีความหมายด้านความสำคัญอีกต่อไป

## รายละเอียดการเปลี่ยนแปลง

### 1. `skills/ava-init/templates/AVA.md` — blockquote ของ section Active Logics

แทนที่ blockquote เดิมทั้งหมดด้วย:

```markdown
> วิธีทำงานเพิ่มเติมที่ owner เปิดใช้ — 1 บรรทัด = 1 logic · ลบบรรทัดเพื่อปิด · เพิ่มผ่าน `/ava-use-logic <name>`
> ไม่มี logic เปิดใช้ → ทำตามกฎของ Ava ตามปกติ
> ลำดับเมื่อขัดกัน: `RULE.md` ชนะเสมอ → การตัดสินใจในคอลัมน์ "owner ตัดสิน" ของ LOGIC.md → logic ที่เปิดใช้ชนะกฎใน AVA.md / SOUL.md (owner อนุญาตแล้วตอนเปิดใช้)
> logic ชนกันเองและยังไม่มีบันทึกในตาราง "เมื่อใช้คู่กับ logic อื่น" → หยุดถาม owner แล้วบันทึกลงตารางนั้นของทั้งสอง logic
> คลัง logic ทั้งหมดอยู่ใน `.claude/ava/logics/` — ดูด้วย `/ava-use-logic list` (path ใน @import เป็น relative กับไฟล์นี้)
```

### 2. `skills/ava-use-logic/SKILL.md`

- กฎด้านบนของ skill: เปลี่ยน "บรรทัดบนชนะบรรทัดล่าง" เป็นลำดับใหม่
- **A2 (owner review):** แสดงตาราง "ชนกับ Ava" ในคำถาม review ด้วย (เรื่อง / Ava / logic / owner ตัดสิน) เพื่อให้ owner เห็นว่าเปิดแล้วอะไรจะเปลี่ยน · ถ้าอยากปรับข้อไหน ให้แก้คอลัมน์ "owner ตัดสิน" ใน LOGIC.md ก่อนเปิด
- **A4:** เปลี่ยนเป็นถามเฉพาะเรื่องที่ชนกับ logic อื่นที่เปิดอยู่ (ข้อ 3 เดิม) · เรื่องที่ชนกับ Ava ไม่ต้องถาม แค่เพิ่มแถวใหม่ลงตาราง "ชนกับ Ava" ถ้าเจอ โดยให้คอลัมน์ "owner ตัดสิน" ว่างไว้ (= ใช้แบบ logic) · ชนกับ `RULE.md` → เขียน `RULE.md ชนะ` เหมือนเดิม
- บันทึกการตัดสินใจเรื่อง logic ชนกันลงตาราง "เมื่อใช้คู่กับ logic อื่น" **ของทั้งสอง logic**
- **A5:** ตัดข้อความ "สลับลำดับบรรทัดได้ถ้าต้องการให้ชนะ logic อื่น"
- **A7 / C:** ข้อความแจ้งผลเลิกพูดถึงลำดับความสำคัญ (`active #n` ใน list ยังแสดงได้ แต่หมายถึงลำดับในไฟล์เท่านั้น)

### 3. `skills/ava-use-logic/scripts/add-import.sh`

ข้อความ blockquote ใน `printf` (กรณี AVA.md รุ่นเก่าที่ไม่มี section) เปลี่ยนเป็นข้อความเดียวกับข้อ 1

### 4. `skills/ava-connector/SKILL.md`

- template LOGIC.md: หัวตาราง "ชนกับ Ava" เปลี่ยนจาก "(owner ต้องยืนยัน)" เป็น "(ว่าง = ใช้แบบ logic)"
- หลักการเขียน: คอลัมน์ "owner ตัดสิน" ยังเว้นว่างเหมือนเดิม แต่ความหมายคือ "ใช้แบบ logic จนกว่า owner จะแก้"
- ขั้นที่ 4: ข้อความ "จุดที่ชนกับ Ava (ต้องตัดสินใจ)" เปลี่ยนเป็น "จุดที่ logic จะเปลี่ยนพฤติกรรมของ Ava" พร้อมบอกว่าถ้าอยากปรับให้แก้คอลัมน์ "owner ตัดสิน" ก่อนเปิดใช้
