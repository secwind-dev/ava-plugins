จัดการความทรงจำของ Ava — เป้าหมายคือ **หาเจอได้จาก INDEX.md บรรทัดเดียว** แล้วเปิดไฟล์ที่ตรงเรื่องทันที

argument ที่รับมา: `$ARGUMENTS`

---

## โครงสร้าง

```
.claude/ava/memories/
├── INDEX.md        ← สารบัญ 1 แถวต่อ 1 ไฟล์ (โหลดทุก session ตาม CLAUDE.md)
├── sessions/       ← สรุปบทสนทนา: YYYY-MM-DD-<slug>.md
├── decisions/      ← การตัดสินใจ + เหตุผล: <slug>.md
├── preferences/    ← ความชอบ / วิธีทำงานของ owner และทีม: <slug>.md
└── facts/          ← ข้อเท็จจริงของโปรเจกต์ / ระบบ / คน / แหล่งข้อมูล: <slug>.md
```

| type | ใส่อะไร | ตัวอย่าง |
| --- | --- | --- |
| `session` | สรุปว่าคุย/ทำอะไรในบทสนทนา | ลบ skill 8 ตัว แล้ว push repo |
| `decision` | เลือกอะไร เพราะอะไร | ใช้ branch main เพราะ ava-doctor อ่าน /main/ |
| `preference` | owner/ทีมชอบให้ทำงานแบบไหน | ถามก่อนลบไฟล์ที่ไม่อยู่ใน git |
| `fact` | ข้อมูลที่ไม่ได้อยู่ใน code / git | repo อยู่ใต้ gh account secwind-dev |

`<slug>` = ภาษาอังกฤษตัวเล็ก คั่นด้วย `-` สั้นและสื่อความหมาย

---

## Format ไฟล์ memory

```markdown
---
title: <ชื่อเรื่องสั้นๆ>
type: session | decision | preference | fact
date: YYYY-MM-DD
updated: YYYY-MM-DD
tags: [tag1, tag2]
related: [decisions/xxx.md]
---

<เนื้อหา — กระชับ ตรงประเด็น>

**Why:** <เหตุผล — บังคับสำหรับ decision / preference>
**How to apply:** <ใช้กับงานต่อไปยังไง — บังคับสำหรับ decision / preference>
```

ไฟล์ `session` ใช้หัวข้อย่อยแทน Why/How:

```markdown
## สรุป
## สิ่งที่ทำ / ตัดสินใจ
## ค้างไว้ / ทำต่อ
```

## Format แถวใน INDEX.md

```
| YYYY-MM-DD | type | [title](path/file.md) | สรุป 1 บรรทัด | tag1, tag2 |
```

- เรียงแถว **ใหม่สุดไว้บนสุด** (ใต้หัวตาราง)
- 1 ไฟล์ = 1 แถวเท่านั้น — ไฟล์ถูกแก้ → อัปเดตแถวเดิม (วันที่ = `updated`) แล้วย้ายขึ้นบนสุด
- สรุปต้องพอให้ตัดสินได้ว่าจะเปิดไฟล์ไหม โดยไม่ต้องเปิดอ่าน

## ขั้นที่ 0 — เตรียมโฟลเดอร์

ถ้ายังไม่มี `.claude/ava/memories/INDEX.md` → สร้างโฟลเดอร์และ INDEX ก่อน:

```bash
mkdir -p .claude/ava/memories/sessions .claude/ava/memories/decisions .claude/ava/memories/preferences .claude/ava/memories/facts
```

แล้วใช้ Write tool สร้าง `.claude/ava/memories/INDEX.md`:

```markdown
# INDEX.md — สารบัญความทรงจำของ Ava

> 1 แถว = 1 ไฟล์ · ใหม่สุดอยู่บน · จัดการผ่าน `/ava-memory`

| วันที่ | ประเภท | ไฟล์ | สรุป | tags |
| --- | --- | --- | --- | --- |
```

## ขั้นที่ 1 — เลือกโหมดจาก argument

| argument | โหมด |
| --- | --- |
| ว่าง | **A. สรุปบทสนทนา** |
| ขึ้นต้นด้วย `find ` | **C. ค้นหา** |
| ขึ้นต้นด้วย `forget ` | **D. ลืม** |
| อื่นๆ | **B. บันทึกเรื่องที่ระบุ** |

ถ้า Ava เรียก skill เองจากบทสนทนา (ไม่ได้มาจาก `/ava-memory`) → เลือกโหมดตามเจตนา: "จำไว้…" = B, "เคยคุย/ตัดสินใจอะไร…" = C, "ลืม…" = D, "บันทึกที่คุยวันนี้" = A

---

## ขั้นที่ 2 — กฎความปลอดภัย (เช็คก่อนเขียนทุกครั้ง)

memories/ ถูก commit เข้า git และแชร์ทั้งทีม — **ห้ามบันทึก**:

- password, token, API key, secret, private key, connection string ที่มี credential
- ข้อมูลส่วนบุคคล (เลขบัตรประชาชน, บัตรเครดิต, เบอร์โทร, ที่อยู่) ตาม `.claude/ava/RULE.md`

เจอข้อมูลเหล่านี้ → ตัดออก / แทนด้วย `<redacted>` แล้วแจ้ง user ว่าไม่ได้บันทึกส่วนนั้นเพราะอะไร

---

## A. สรุปบทสนทนา

1. ทบทวนบทสนทนาทั้งหมดใน session นี้
2. สร้างไฟล์ `sessions/<วันนี้>-<slug>.md` (ถ้ามีไฟล์วันเดียวกันเรื่องเดียวกันแล้ว → แก้ไฟล์เดิม)
3. แยก **decision / preference / fact** ที่ควรจำระยะยาวออกเป็นไฟล์ของตัวเองตามขั้น B (ข้อ 2–5) แล้วใส่ไว้ใน `related` ของไฟล์ session
4. **ไม่บันทึก** สิ่งที่ดูได้จาก code, git log หรือ CHANGELOG อยู่แล้ว — เก็บเฉพาะ "ทำไม" และ "บริบท" ที่หายไปถ้าไม่จด
5. อัปเดต INDEX.md ทุกไฟล์ที่สร้าง/แก้ แล้วไปขั้นสุดท้าย

## B. บันทึกเรื่องที่ระบุ

1. จัด type ตามตารางด้านบน (ไม่แน่ใจ → ถาม user)
2. **หาไฟล์เดิมก่อน** — ค้นใน INDEX.md (title / สรุป / tags) และ `grep -ril "<keyword>" .claude/ava/memories/`
    - เจอเรื่องเดียวกัน → แก้ไฟล์เดิม อัปเดต `updated` (ไม่สร้างซ้ำ)
    - ข้อมูลใหม่ขัดกับของเดิม → แทนที่ของเดิม และระบุใน body ว่าเปลี่ยนจากอะไร
3. ไม่เจอ → สร้างไฟล์ใหม่ใน `<type>s/<slug>.md` ตาม format
4. ถ้าเกี่ยวกับไฟล์อื่น → ใส่ใน `related` ทั้งสองฝั่ง
5. อัปเดต INDEX.md แล้วไปขั้นสุดท้าย

## C. ค้นหา

1. อ่าน INDEX.md (ถ้ายังไม่อยู่ใน context) แล้วกรองแถวที่ตรงคำค้น — ดูทั้ง วันที่ / ประเภท / สรุป / tags
    - คำถามเชิงเวลา ("วันนี้", "เมื่อวาน", "สัปดาห์นี้") → แปลงเป็นช่วงวันที่จริงแล้วกรองคอลัมน์วันที่
2. ไม่เจอใน INDEX → `grep -ril "<คำค้น>" .claude/ava/memories/`
3. เปิดอ่าน **เฉพาะไฟล์ที่ตรง** แล้วตอบพร้อมอ้างอิง path
4. ไม่เจอเลย → บอกตรงๆ ว่าไม่มีบันทึกเรื่องนี้ ห้ามเดา

## D. ลืม

1. ค้นหาไฟล์ที่ตรงตามขั้น C
2. แสดงรายการไฟล์ที่จะลบ แล้ว **confirm กับ user ก่อนลบ**
3. ลบไฟล์ + ลบแถวใน INDEX.md + ลบ path นั้นออกจาก `related` ของไฟล์อื่น

## ขั้นสุดท้าย — แจ้งผล

```
🧠 บันทึกแล้ว
📄 <path ที่สร้าง/แก้> — <สร้างใหม่ | อัปเดต>
🗂️ INDEX.md อัปเดตแล้ว
```

(โหมด C แสดงคำตอบ + path อ้างอิง, โหมด D แสดงรายการที่ลบ)

> 💡 memories/ อยู่ใน git — ถ้าเจอ merge conflict ใน INDEX.md ให้เก็บแถวของทั้งสองฝั่ง แล้วเรียงตามวันที่ใหม่
